# ADR-0003: 悲观情景不再叠加"收入持续下降 + 支出持续上涨"

- 状态:accepted
- 日期:2026-09-06
- 决定人:Rinto(@LingyiLuan)
- 触发:M1 验收发现 Profile.sample 悲观情景"100 岁前未达";悲观情景多重不利假设复利叠加,输出退化为"永远不可达"。

## 问题(≤ 3 句)

悲观情景同时假设峰值后收入每年 −1%、支出每年 +1%、真实收益仅 3%,三者按年复利叠加,几十年后差距被指数放大,普通储蓄率用户几乎必然"未达"。"悲观=未达"对用户没有信息量,也违背"归因指向用户自己的行为"的语气规范。悲观情景应表达"更保守的市场与提取假设",而不是"一切同时永远变坏"。

## 新旧参数表

| 参数(仅悲观情景) | 旧 | 新 | 说明 |
|---|---|---|---|
| 真实年化收益 | 3% | 3.5% | 与 3.5% 提取率同一套历史假设,TODO(calibrate) |
| 峰值后收入实际增速 | −1% | 0% | 不再叠加收入持续下降 |
| 支出实际增速 | +1% | 0% | 不再叠加支出持续上涨 |

| 参数(全情景) | 旧 | 新 | 说明 |
|---|---|---|---|
| 行业峰值修正 tech | 其他 −3 / cnMainland −5 | 其他 −2 / cnMainland −3 | 收敛过强的行业惩罚,TODO(calibrate) |

悲观情景与其余情景的差异保留在:提取率 3.5%(自由线 ×28.57)、收益 3.5%、峰值前增速 2%、峰值年龄更早、自控力差支出 +3%(仅悲观)。

## 议会

### 产品经理
判断:同意。"悲观=未达"让免费结果失去传播价值,且吓人不导向行动。
证据来源:M1 验收输出(PR #5 证据栏,悲观未达);BRIEF §7 语气规范"不制造恐惧"。

### UI 设计师
判断:同意。Reveal 三情景 chip 需要三个可比的数字;补充:未达时仍要有可行动文案(见结论追加项)。
证据来源:BRIEF §6 Reveal 验收;docs/design 四屏稿三 chip 布局。

### iOS 工程师
判断:同意。参数为 EngineParams 单点改动,金标固件不受影响(golden.json 注入零增长参数,与情景参数解耦)。
证据来源:GoldenTests 注入 flatParams 的设计;swift test 11/11 绿。

### 全栈工程师
判断:同意。改动纯参数层,引擎仍纯 Foundation;requiredSavingsRate 二分搜索复用 simulate,H5 版可照搬。
证据来源:golden.json 未触碰;EngineParams 单文件 diff。

## 结论

选择:按新旧参数表修改悲观情景与行业修正;悲观情景的"悲观"由提取率与收益承担,不再由收入/支出增速承担。
理由(一段):情景带宽应表达市场与提取假设的不确定性,而非把所有人生不利假设复利叠加;叠加后输出恒为"未达",既无信息量又制造恐惧,违背产品语气规范。
追加:freedomAge 为 nil 时 UI 显示"把储蓄率提到 X% 可在 65 岁前自由",X 由引擎 `requiredSavingsRate(for:)` 二分搜索给出(引擎与测试 M1 落地,UI M7 实现)。

## 后果
- 要做:EngineParams 四处数字 + BRIEF §3.2 表 + science-basis.md 同步;引擎加 requiredSavingsRate + 测试;BRIEF §6 Reveal 验收追加一句。
- 不做:不改 golden.json;不改其余两个情景;不改提取率。
- 回滚条件:校准数据(国家统计局分行业工资、历史真实回报)表明新参数系统性偏乐观。
