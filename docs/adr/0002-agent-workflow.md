# ADR-0002: 智能体工作流与信任阶梯

- 状态:accepted
- 日期:2026-09-02
- 触发:项目初始化

## 问题
如何让智能体的产出从"不可信"逐步走到"可自动合并",同时保证人类不必逐行读代码。

## 选项
A. 人类逐行审所有 PR。
B. 智能体自动合并所有 PR。
C. 分级:策略持有合并键;智能体自证;独立评测集智能体不可写;按记录逐级放权。

## 议会
### 产品经理
判断:C。速度来自减少人类等待,而不是取消人类。
证据来源:行业实践——AI 只做"审阅/评论",人类或策略持有合并;自动批准低风险 PR 即可把交付周期缩短约 74%,不需要自动合并。
对其他角色的回应:同意全栈关于"独立评测集"的要求作为放权前提。

### UI 设计师
判断:C,补充:UI 变更的证据必须是截图/录屏,不能是代码。
证据来源:Lauren Tan(前 Cursor,现 SpaceX AI)的做法——让智能体自己启动 App、操作 UI、开模拟器、抓性能记录来验证。
对其他角色的回应:接受。

### iOS 工程师
判断:C。分支保护 + CI + 变更预算 + 受保护路径是机械可执行的策略;金标固件由 CODEOWNERS 锁定,智能体不能"改数字让测试变绿"。
证据来源:"智能体提案、流水线裁决"——评测集独立于智能体、失败即拒绝、通过才路由给人类。
对其他角色的回应:否决 B——PR diff 本身是不可信输入,自动合并一切会让提示注入直通生产。

### 全栈工程师
判断:C。允许名单路径(docs、本地化、设计稿)可 L3 自动合并,因为它们不可能破坏构建或支付。
证据来源:同上。
对其他角色的回应:同意。

## 结论
选择:C,细则见 AGENTS.md §3–§4。

## 后果
- 要做:main 分支保护;CI 三个 job(engine / app / policy);PR 模板强制"证据"。
- 不做:让任何智能体拥有合并权限。
- 回滚条件:任何一次因智能体变更导致的线上回滚 → 相关任务类降一级并记录。
