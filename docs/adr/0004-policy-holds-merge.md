# ADR-0004: 合并键交给策略——L1/L2 CI 绿即自动合并,人类合并后审阅

- 状态:accepted
- 日期:2026-09-06
- 决定人:Rinto(@LingyiLuan)
- 触发:M0–M3 期间七个 PR(#3–#9)积压,全部 CI 绿却等待人类合并;人类合并成为瓶颈。

## 问题(≤ 3 句)

工作流要求人类合并 L0–L2,但人类不常在线,PR 链式叠加导致后续 PR 的 diff 与 CI 状态互相污染。合并前人工审阅的价值,在变更预算(≤400 行)、受保护路径检查、三项必需状态检查已机械执行的前提下,主要剩"看一眼"。审阅可以移到合并后,回滚成本低(`gh pr revert` 一键)。

## 议会

### 产品经理
判断:同意。里程碑节奏被合并等待打断,七个 PR 积压即证据。
证据来源:PR #3–#9 全部 OPEN 的时间线;AGENTS §8"人类不在线时不停摆"本已是原则。

### UI 设计师
判断:同意,但 UI 目视验收仍在合并后 PR 评论里做,发现问题走回滚或修正 PR。
证据来源:AGENTS §4.2(人类目视验收条款保留不变)。

### iOS 工程师
判断:同意。分支保护要求三项状态检查,squash 合并 + 删分支保持历史线性;`gh pr revert` 可一键回滚任何 squash 提交。
证据来源:GitHub 分支保护配置(2026-09-06 生效);ci.yml 三个 job。

### 全栈工程师
判断:同意。受保护路径(固件、EngineParams、.github、AGENTS/CLAUDE)仍强制 L0 标签,策略防线未降。
证据来源:ci.yml Policy job 的路径正则与预算检查。

## 结论

选择:L1/L2 改为"CI 绿即自动合并,人类合并后审阅";L0 不变(仍需 `L0-human-reviewed` 标签,即人类事前批准)。智能体开 PR 后立即 `gh pr merge --auto --squash`。
理由(一段):人类合并成为瓶颈,七个 PR 积压;补偿机制已经在位——变更预算、受保护路径、`gh pr revert` 一键回滚。

## 后果
- 要做:AGENTS.md §3 / §4.1 改写;新增 §4.4 回滚协议(人类说"revert #N" → 智能体执行 `gh pr revert` 并汇报)。
- 不做:不动 L0;不动分支保护与三项必需检查;不动变更预算。
- 回滚条件:出现一次"自动合并进 main 且回滚未能一键完成"的事故,即恢复人类合并。
