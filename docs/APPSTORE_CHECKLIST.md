# WealthClock 上架清单(第一次上架版)

> 这份是给你自己看的,不是给 Claude Code 的。顺序按时间排,括号里是大致耗时。
> 原则:**能提前做的账号/协议类事项今天就做**,它们的等待时间和开发并行。

---

## 阶段 A · 今天就做(并行于开发)

### A1. 注册 Apple Developer Program(等待 1–2 天)
- 用你现有的 Apple ID(必须已开双重认证),在 iPhone 的 **Apple Developer** App 里或 developer.apple.com 上注册。
- 选 **Individual(个人)**。99 美元/年,用能付外币的信用卡。个人身份验证通常 24–48 小时;组织账号要 D-U-N-S 编号,要 1–2 周,现阶段不需要。
- 个人账号的代价:App Store 上"卖家"显示你的真实姓名。将来要换成公司名(比如香港公司),需要另开组织账号并做 App 转移,所以如果你已经确定要用公司名,现在就决定。
- 可能被要求上传身份证件照片,这是正常流程。

### A2. 申请 Agreements, Tax, and Banking(等待 1–3 天)
账号批下来后立刻去 App Store Connect → **Agreements, Tax, and Banking**:
- 接受 **Paid Apps Agreement**(免费 App 也建议先签,否则 IAP 测不了)。
- 填税表:非美国税务居民填 **W-8BEN**。
- 填收款银行:需要能收美元电汇的账户。大陆银行账户走 SWIFT 可以收,但到账慢、有时被问用途;很多大陆个人开发者用香港账户。这一步不影响提审,但**不填完 IAP 不能上线**。

### A3. 准备两个公开网页(30 分钟)
提审必须有 **隐私政策 URL** 和 **支持 URL**。用 GitHub Pages 即可:
- `wealthclock.app/privacy`:内容 Claude Code 在 M8 会生成(核心一句:所有计算在设备上完成,不收集任何数据)。
- `wealthclock.app/support`:一个邮箱 + FAQ 三条。
- 域名今天买。没域名就先用 `<你的用户名>.github.io/wealthclock/`。

### A4. 决定地区(5 分钟,但要想清楚)
**第一版不上中国大陆商店。** 原因:大陆商店要求工信部 App ICP 备案号,这是一个需要大陆主体的独立合规流程;而且命理类内容在大陆的审查风险高。首发地区建议:美国、加拿大、香港、台湾、新加坡、马来西亚、澳大利亚、日本、英国。大陆用户后续用 H5 版本承接。

## 阶段 B · 开发期间做(M5 之后)

### B1. 在 App Store Connect 建 App 记录
- **My Apps → +**:名称 `WealthClock`(30 字上限,全球唯一,先占住)、主语言 简体中文、Bundle ID 选 Xcode 里那个、SKU 随意。
- **副标题**(30 字):"用数学算命 · 算出你的财务自由年龄"
- **关键词**(100 字,逗号分隔,不要重复名称里的词):财务自由,FIRE,储蓄率,退休计算器,复利,财运,理财,八字,人类图,财富自由
- **分类**:主 Lifestyle(生活),副 Finance(财务)。不要把主分类设成 Finance,那会引来更严格的审核。
- **年龄分级**:问卷里全部选"无",评级 4+。命理内容不属于问卷里任何一项。

### B2. 建 IAP 产品
- **Features → In-App Purchases → +**:类型 **Non-Consumable(非消耗型)**,Product ID `app.wealthclock.report.full`(必须和代码一致),参考名"完整推演报告"。
- 定价档:建议美区 **$4.99 或 $6.99**。第一版别定 $9.99 以上——我们的差评研究里 30.5% 的差评是钱,先用低价换评价。
- 每个 IAP 要有本地化名称、描述、和一张**审核截图**(付费墙的截图)。
- IAP 状态要是"Ready to Submit",并在提交 App 版本时**勾选一起送审**——第一次上架最常见的坑是 IAP 忘了附在版本里,审核员买不了就拒。

### B3. App 隐私"营养标签"
**App Privacy** 里选 **Data Not Collected**。这是我们 v1 完全离线的最大红利,也是审核员最省心的选项。前提:代码里真的没有任何联网 SDK——Claude Code 的指令里已经禁了。

### B4. 截图
- 必需尺寸:**6.9 英寸**(iPhone 16 Pro Max 一档)与 **6.5 英寸**,各 3–10 张。iPad 不支持就在 Xcode 里把 iPad 从支持设备去掉,否则也要交 iPad 截图。
- 5 张顺序:汇票结果卡(最吸睛的放第一张)→ 揭晓页 → 问卷"你炒股吗" → 推演曲线 → 历史。
- 截图里**不能有 App 里没有的功能**,这是 2.3 条拒审的常见原因。Claude Code M8 会用模拟器脚本生成。

## 阶段 C · 提审(M8 完成后)

### C1. TestFlight 先跑三天
- Xcode → Product → Archive → Distribute → App Store Connect。上传后在 TestFlight 里加你自己和 3–5 个朋友(内部测试不需要审核)。
- 真机上验证:购买流程用**沙盒账户**(App Store Connect → Users and Access → Sandbox)走一遍,删 App 重装再"恢复购买"。
- 出口合规:Info.plist 里已经写了 `ITSAppUsesNonExemptEncryption = NO`,上传时不会再问。

### C2. 填版本信息并提交
- **What's New**:首版写"首次发布"。
- **审核备注(App Review Information → Notes)**:用 CLAUDE.md §9 那段英文,再加一句中文说明"应用完全离线,无需账号"。不需要提供测试账号,因为没有登录。
- **联系信息**填真实电话和邮箱,审核员偶尔会打电话。
- **版本发布方式**选 **Manually release**(手动发布),这样审核通过后你能挑一个和小红书内容同步的时间点上线。
- 提交。

### C3. 审核期间
- 目前审核通常 24–48 小时,第一次可能到 3–5 天。
- 2024 年苹果审了 777 万次提交,拒了约 193 万次,大约四分之一。最常见的原因:崩溃与 bug(2.1)、隐私政策缺失或不符(5.1.1)、元数据与截图不符(2.3)、无账号删除入口(5.1.1(v))、最低功能要求(4.2)。我们的设计已经绕开了其中四条(无账号、离线、真实功能、截图由真机生成),剩下就是别崩。
- 若被拒:在 Resolution Center 里**先礼貌回复问清楚**,不要立刻改代码——一半的拒审是沟通问题,回复说明后可直接通过。真要改,改完重新上传 build 再提交,不用重填元数据。

### C4. 通过后
- 手动发布前:小红书第一条内容排好,发布当天同步。
- 上线 72 小时内每天看崩溃报告(Xcode Organizer)和评论。
- 第一批评论回复要快,尤其是三星以下——我们的差评研究里,"回复了差评"是唯一能扭转评分趋势的动作。
